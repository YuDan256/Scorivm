**序 言**

在我们的时代，软件建筑毫无节制且毫无理智地无限膨胀，机器在臃肿的函数库的重压之下发出痛苦的呻吟。而本作旨在回归古老而质朴的美德。伟大不在于繁复，而在于简练与纯粹。

Scorivm 是一个基于裸机完全构建的编译器，极其微小却蕴含巨大能量，其体积仅有 **240 KB**。它不依赖任何外部工具，也不被臃肿的链接器所累。它读取代码，将其净化，并直接转化为具有可执行格式的 X86_64 机器指令。这里没有浮华的装饰与弄虚作假之地；这里是仅存绝对真理的殿堂，是人类智慧与硅片最深层结构交融之所。本作是一次有力的证明：只要我们保持思想的严谨与克制，便依然能以微末之物铸就伟大之作。


### 卷 一 ： 论 编 译 器 架 构

这件作品绝非偶然写就，而是凭借极高的技艺与理性构建而成。为了让机器毫无阻碍地以光速运行，它遵循以下架构法则：

**I. 词法读取与真理之树：** 我们的读取器在执行其功能时，不依赖任何外部奴役或生成工具。它接收原始代码，将其切割成神圣的片段，并从混沌中提取出逻辑之树（AST）。这棵树随后转化为中间表示（SSA），在此形态下，一切变量仅诞生与受赋值一次。

**II. 十一忠将与零溢出：** 在战场上，内存（RAM）不仅迟钝而且充满变数。因此，通过图着色艺术，我们召唤了十一个物理寄存器进入战场。转瞬即逝的变量被收容于这些更为迅捷的护卫中，以确保没有任何数据会被驱逐并溢出到深渊般的堆栈之中。

**III. 坦途与废除占卜：** 现代处理器在企图占卜未知的执行路径（分支预测）上浪费了大量时间。在我们的架构中，当遇到 `si`（if）条件时，彻底废除了这种占卜戏法。Scorivm 通过 `CMOVcc` 条件拷贝指令，使得指令流变为一条直线畅通的河流。机器永远不会犯错，因为它从不猜测。


### 卷 二 ： 论 语 言 的 本 性 与 律 法

Scorivm 的语言绝非其他语言的附庸，而是裸金属（硬件底层）的绝对主宰。它依靠以下律法进行统治：

**I. 摒弃蛮族之枷锁：** Scorivm 彻底拒绝 C 标准库。为了在没有任何操作系统阴影的情况下触碰机器，它仅通过 `barbara`（FFI 接口）这扇唯一的大门与内核深处进行交流。

**II. 阵列、军团与游标：** 内存受到极其严苛与透明的管制。`via` 是毫无边界的裸游标；`cohors` 是携带精确长度的重装军团（胖指针切片）。在这些形态之间，绝不容忍任何隐式的暗中转换。

**III. 微粒与实密结构：** 为了统治底层硬件与网络协议，`forma densa`（实密结构）强制将数据压实，不留丝毫缝隙。借助 `mica`（位域），程序员可以直接对最微小的二进制比特进行无情切割与拼接。

**IV. 辅音骨架：** 为了不让书写者的手指疲惫，律法允许将古典长词缩减为纯粹的辅音骨架。于是 `forma` 化为 `frm`，`cohors` 化为 `crs`，`mica` 化为 `mic`，`aliter` 化为 `alt`。凡人的眼睛乐见其简短，而编译器的眼睛在 AST 之树中知晓它们本为一体。


### 卷 三 ： 巅 峰 对 决

为了检验武器的威力，这台机器被召唤进入计算斐波那契数列的宏大战场：递归执行 `fib(40)`。在此过程中，会触发超过两亿四百万次递归调用。若是将 Scorivm 与庞然大物 MSVC 进行比较，你会发现它实现了惊人的对等与胜利：

* **营阵规模：** 令人畏惧的巨兽以吉字节（GB）为单位衡量。而 Scorivm 仅仅占据 **240 KB** 的单文件空间。
* **武装极速：** 巨兽需要耗费 13 毫秒，才能将代码锻造成钢铁。而 Scorivm 在无声无息间，仅需 **11 毫秒** 便如闪电般完成。
* **兵器尺寸：** 巨兽的产物文件需要占据 85 KB。而 Scorivm 锻造出的纯粹枪尖，仅仅只有 **2 KB**。
* **沙场交锋：** 在硅片战场上，我们的机器掌握着四个境界的完美战术，以此将宿敌斩落：
  * **-O0 (毫无修饰)：** 548 毫秒。
  * **-O1 (第一战术)：** 326 毫秒。与巨兽并驾齐驱。
  * **-O2 (边界展开)：** 101 毫秒。将递归的基底在平原上彻底展开。
  * **-O3 (绝对折叠)：** 7 毫秒。编译器在程序运行之前便已洞察并折叠了最终的答案。此乃“战前之胜”。


### 卷 四 ： 论 主 宰 者 的 沉 睡

如果你在使用纯粹的电池储能供给时运行这台机器，其执行时间会骤然增加到 **约 567 毫秒**。许多人将其视为缺陷，但这实则是物理学定律的体现，是纯粹主义的胜利。当你运行那些臃肿的软件建筑时，它们会向系统倾泻大量的请求与警报，导致系统内核受到惊吓，从而立刻激发绝对的电力狂潮。然而 Scorivm 是如此宁静，如此纯粹，以至于它不会产生任何无谓的延迟。主宰者根本感受不到它的存在，因此继续保持沉睡，处理器也被留在了最底层的功耗本相。这正是裸露且冰冷的硅片本身最真实的心跳。


### 卷 五 ： 仪 式 与 咒 语

若要将这台机器从源代码中唤醒，仅需遵守 *CMake* 律法：
```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

请使用以下咒语，来编译代码并洞悉这神圣的技艺：
```bash
./bin/scorivm tests/fib.sco -o fib.exe
./bin/scorivm tests/fib.sco -O3 -o fib.exe
./bin/scorivm tests/fib.sco -o fib.exe --emitte-ir
./bin/scorivm tests/fib.sco -o fib.exe --emitte-asm
```


### 卷 六 ： 经 文 示 例

请看两幅艺术的化身。其一为纯粹逻辑，其二为主宰底层硬件。

**示例 I：计算与逻辑**
```scorivm
actio fib(n: medius) -> medius {
    si (n <= 1) redde n;
    aliter redde fib(n - 1) + fib(n - 2);
}

actio princeps() -> medius {
    scribe("Calculando... Exspecta!\n");
    sit res: medius = fib(40);
    scribe("Resultatum: ", res, "\n");
    redde 0;
}
```

**示例 II：主宰裸机 (Bare-Metal)**
```scorivm
forma densa edita RegistrumStatus {
    sit paratus: logica mica 1; 
    sit signum: p8 mic 3;      
    sit _: p8 mic 4;           
}

// 外部函数名称必须与动态链接库中的真实 C 符号严格一致
actio bbr("kernel32.dll") WriteFile(
    hFile: via nhl,
    lpBuffer: via RegistrumStatus,
    nNumberOfBytesToWrite: p32,
    lpNumberOfBytesWritten: via p32,
    lpOverlapped: via nhl
) -> lgc;
```
